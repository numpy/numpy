``f2py`` call-back failures are no longer printed to stderr
-----------------------------------------------------------
When a Python call-back raised, or returned a value that could not be
converted, the code generated by ``f2py`` wrote diagnostics such as
``capi_return is NULL`` and ``Call-back cb_fun_in_foo__user__routines failed.``
to stderr next to the exception it propagated. Only the exception is reported
now, and it carries the context that used to be printed: an array result of
the wrong shape names the call-back, a character result that is not ``bytes``
names the type received, and a call-back argument list that cannot be built
(a call-back that is not callable, that requires more arguments than are
passed, or a ``PyCapsule`` given extra arguments) states the reason instead of
only ``failed in processing argument list``. The call-back trace is still
printed for modules built with ``--debug-capi``.

``f2py`` reports call-backs that return no value with a ``RuntimeWarning``
--------------------------------------------------------------------------
A call-back declared as a function whose Python implementation returns no
value is now reported with a ``RuntimeWarning`` instead of a
``Warning: call-back function ... did not provide return value`` line on
stderr, so that it can be filtered like any other warning. When warnings are
turned into errors, the call-back fails and the exception propagates to the
caller of the wrapped routine.
