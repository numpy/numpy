Shape-typing for the main ``numpy`` namespace
---------------------------------------------
The functions in the main ``numpy`` namespace now use the shape-types of their input(s)
to infer the shape-type of the returned array(s). Due to limitations of Python's type
system, this usually only applies to low-rank array-likes.

.. code-block:: python

    a = np.array([[1.0, 2.0], [3.0, 4.0]])
    x = np.array([1.0, 2.0])

    reveal_type(a)
    # before: ndarray[tuple[Any, ...], dtype[Any]]
    # after:  ndarray[tuple[int, int], dtype[float64]]

    reveal_type(np.stack([x, x]))
    # before: ndarray[tuple[Any, ...], dtype[Any]]
    # after:  ndarray[tuple[int, int], dtype[float64]]

    reveal_type(np.sum(a, axis=0))
    # before: ndarray[Any, Any]
    # after:  ndarray[tuple[int], dtype[float64]]

    reveal_type(np.dot(a, x))
    # before: Any
    # after:  ndarray[tuple[int], dtype[float64]]

    reveal_type(np.percentile(a, [25, 75], axis=0))
    # before: Any
    # after:  ndarray[tuple[int, int], dtype[float64]]

This allows type-checkers to catch shape mismatches that previously went unnoticed:

.. code-block:: python

    def center(v: np.ndarray[tuple[int], np.dtype[np.float64]]) -> None: ...

    mu = np.mean(a, axis=0, keepdims=True)
    center(mu)
    # before: no error
    # after:  error: incompatible type "ndarray[tuple[int, int], dtype[float64]]"
